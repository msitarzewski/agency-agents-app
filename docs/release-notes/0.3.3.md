## Agency Agents v0.3.3 — 2026-11-28

Windows installers are now code-signed, so Smart App Control no longer blocks them, and the app tells you when it
finds catalog files it can't read instead of quietly leaving them out.

### Downloads

- **macOS** (Apple Silicon & Intel) — signed + notarized `.dmg`, launches without warnings. macOS 13+.
- **Linux** (x86_64) — `.deb` (Debian/Ubuntu), `.rpm` (Fedora/RHEL/openSUSE), or the portable `.AppImage`.
- **Windows** (x64 & ARM64) — `.exe` installer, now **code-signed**.

Or visit [agencyagents.app](https://agencyagents.app).

### Fixes

**Windows installs on PCs with Smart App Control.** The v0.3.2 installer was unsigned, and Windows 11's Smart App
Control blocks unsigned installers outright, with no "Run anyway" (agency-agents#1181). Both Windows installers are
now signed.

**You can see when the catalog has files the app can't read.** A catalog file with broken frontmatter (for example
an unquoted `: ` in a description) used to vanish from the agent list without a word, so a division could show 57
agents when the folder held 58 (#79). The app now lists every such file in **Settings → Catalog** with the reason,
including the YAML error and its line in the file, and the sidebar shows "1 file couldn't be read". If two files
share a name, the first one wins and the second is listed.

**Clone badges count every agent.** Settings showed fewer agents for a catalog clone than the catalog view did,
because agents in subfolders (the game-engine agents) weren't counted (#119; thanks @HerbertGao).

**Linux AppImage subprocesses.** The app now strips the Python paths added by the AppImage launcher before
starting external tools. This prevents the bundled environment from breaking Python-based subprocesses
(#129, thanks @birnbaummalte-lang).

**Theme menu.** The Light, Dark, and System choices stay above sticky headers in Activity and other views
(#132, thanks @pierrejochem).
